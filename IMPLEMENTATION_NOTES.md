# Implementation notes

Deviations and judgement calls relative to SPEC.md / DECISIONS.md.

- **web_accessible_resources** exposes the two fonts plus `lib/settings.js`, `lib/css.js`, `lib/inject.js` to `<all_urls>` with `"use_dynamic_url": true`. Fonts are needed because injected `@font-face` is fetched by the page. The three lib files are needed because the "all sites" content script cannot use static imports and loads them with dynamic `import()`. With dynamic URLs the resource URLs contain a per-session id instead of the fixed extension id, so a page cannot fetch `chrome-extension://<id>/...` by the fixed id. Verified in Chromium e2e: the content script still loads the modules, the dyslexia font loads on the all-sites path (also on a page served with `default-src 'self'`), and a fetch by the static id is blocked. NOT hidden: a styled page can still see the per-session font URL and the `#accessease-style` element (fallback path), so a site that looks can tell AccessEase is active. See DECISIONS.md 8.
- **CSS injection** uses one function (`lib/inject.js`) that swaps a constructable stylesheet (`adoptedStyleSheets`, immune to page CSP), with a `<style id="accessease-style">` fallback, instead of `insertCSS/removeCSS`. Passing `''` removes it. The panel and the content script share it (same isolated world).
- **Text scale**: `css.js` emits tokens and `inject.js` resolves them against the page's ORIGINAL computed sizes (measured with our style removed): `html{font-size:<round1(orig root px * N/100)>px}` (absolute, so `html{font-size:62.5%}` sites get exactly N%, not 2.4x). A floor `max(1em, <median sampled paragraph px * N/100>)` on body-text elements is kept only when sampled text did not grow with the root (px-sized sites); rem/em sites keep their size hierarchy. The content script re-measures at DOMContentLoaded/load because at `document_start` the page CSS is not loaded yet. The floor block also holds heading floors (h1 1.6, h2 1.35, h3 1.2, h4-h6 1.05 x base, `max(1em, calc(base * m))`) so headings never end up smaller than body text on px sites, and `height:auto` on inputs so they do not clip at 200%. Limits: on px-sized sites small print inside body-text elements is lifted to the paragraph size, and leaf `div`/`span` text is not scaled (see Known limitations). `zoom` is not used.
- **Reduce motion** uses ~0 duration (not `animation:none`) so entrance animations still end in their final visible state.
- **Active tab limits:** activeTab access lasts only for the tab/origin the user clicked the icon on. A status line under the header ("Active on this page" / "Not active on this page" plus an "Apply on all sites" button) is recomputed on open and on tab switch. Without host access `tab.url` is unavailable, even for chrome:// pages, so the copy is chosen by `url == null` (NO_ACCESS) versus `isProtectedUrl(url)` (PROTECTED); when the url is hidden, a failed `executeScript` whose Chrome error text names chrome://, chrome-extension:// or the extensions gallery is also treated as PROTECTED (a heuristic on Chrome's wording; the fallback is the NO_ACCESS copy).
- **All-sites orchestration** lives in `lib/panel-logic.js` (not web-accessible; unit-tested with a chrome stub). Turning it OFF clears the styling on ALL open tabs, including the active one, while the permission is still held, then drops the permission and re-checks `permissions.contains` (sticky notice if Chrome still holds access; "some tabs could not be cleared and may need a reload" if a tab that should have been reachable failed; browser-protected pages never count as failures). The panel then re-applies its own settings to the active tab as usual, so the active tab can still look styled while the panel is open and has access (activeTab). Turning it ON registers the content script and immediately styles already-open tabs with `executeScript`; tabs that cannot be reached get "Other tabs will update when you reload them." `ensureConsistent` unregisters the script whenever the setting is off or the permission is gone, and the service worker calls it on install, startup, `permissions.onAdded` and `permissions.onRemoved` (revoking from chrome://extensions is handled). "Reset my settings" resets text, contrast, font and motion only (the all-sites choice is kept) and shows a self-clearing confirmation in `#notice`.
- **Two windows:** the panel listens to `chrome.storage.onChanged` and adopts settings written by another window's panel (`adoptExternalSettings`). Changes are ignored while its own saves are in flight and when they equal what it shows, so there is no feedback loop.
- **Forced colors (Windows High Contrast):** `@media (forced-colors: active)` maps switch tracks/knobs, the selected segment, the status dot, buttons and focus rings to system colours; the selected segment also has a check mark (a non-colour cue in every mode). Emulated and inspected in Chromium; real Windows High Contrast themes were not tested.
- **Inactive state:** while AccessEase cannot act on the page, the page-control cards are dimmed (opacity .8, not .6: lower values fail axe contrast for the hint text) but stay usable; the all-sites card is never dimmed.
- **Panel messages:** save-failure, load-failure and permission notices live in a separate sticky `#sticky-notice` (role=alert) that the per-apply `#notice` never overwrites. A settings load failure falls back to defaults. `migrate` returns defaults if a migration step is missing. The -/+ buttons are never disabled (focus is kept); at a limit they announce "Already at the largest/smallest size".
- **Manifest CSP** for extension pages: `default-src 'self'; script-src 'self'; object-src 'none'; connect-src 'none'; img-src 'self'; style-src 'self'; font-src 'self'; frame-src 'none'; base-uri 'none'; form-action 'none'`. The panel needed no changes; e2e asserts no violations and that inline script is blocked. (Test code must not use `addStyleTag`; use CSSOM.)
- **Contrast mode** gives button-like elements a 2px border, colours `::before/::after` with the foreground (never a background), and leaves photos and videos untouched (CSS background images are kept). Button-like elements and badge/chip/pill/tag elements lose their background image (gradients would defeat the flat colours); `:invalid` and `[aria-invalid="true"]` fields are exempt from the solid button border and get a dashed 2px outline in the foreground colour instead. Dyslexia mode changes font, line-height 1.6 and word-spacing .05em only (no letter-spacing) and no longer exempts genuine `<i>` italics (only `i[class]` icon elements). Contrast labels are "Black on white" / "White on black"; the panel stacks the segments under 290px and does not overflow at 260px.
- `minimum_chrome_version` is 114 (side panel API).
- Added `lib/pages.js` (protected-URL check), `lib/allsites.js`, `lib/inject.js`, `scripts/build.mjs` (dependency-free zip writer; also checks manifest-referenced files exist).
- `build.mjs` also checks `content/apply.js` (registered at runtime, not in the manifest) and the panel's css/js exist, skips dotfiles, `*.map` and `*~`, and deletes old zips in `dist/` before writing. CI fails a tag build if the tag is not `v` + the manifest version.
- `package.json` does not list eslint peer packages beyond `eslint`, `@eslint/js`, `globals`.

- **Read aloud was cut** (user decision, see DECISIONS.md 15): `tts.js`, `chunk.js`, text extraction, the panel card, the `tts` settings key and their tests are gone. Old stored data that still has `tts` is tolerated (unknown keys are dropped by `normalize`). Permissions are unchanged; `scripting` is still needed for CSS injection.

## Real-browser end-to-end tests (`npm run test:e2e`)

`e2e/` drives the unpacked extension in Playwright's bundled Chromium (headed by default; `E2E_HEADLESS=1` for new headless) and writes `docs/e2e-report.md` plus four 1280x800 screenshots in `docs/screenshots/`. `npm test` stays the fast unit run. CI has a separate, non-blocking `e2e` job (xvfb). The test file header states exactly what is and is not covered; in short, the toolbar click (activeTab) and the native all-sites permission prompt cannot be automated, so apply/all-sites run against a temp copy of the extension whose manifest has the host permission granted at install. Everything else is the shipped code, and install-time permissions are checked on the unmodified manifest.

Unit tests: `tests/inject.test.js` (fake DOM), `tests/allsites.test.js`, `tests/panel-logic.test.js` and `tests/background.test.js` (chrome stubs), `tests/pages.test.js`. E2E fixtures: `rem62.html`, `px.html`, `contrast.html`, `csp.html` (served with `default-src 'self'`), `paper.pdf`. Measured pixel widths (borders, outlines) are DPI-scaled on Windows, so e2e asserts them with tolerance.

Still not verified in automation: the permission prompt and activeTab grant, `permissions.remove` (the "turn all-sites off" cleanup), the docked side panel chrome, branded Chrome.

### Fixes made after the e2e run

1. **Contrast control looked broken** (`sidepanel/sidepanel.css`): the selected segment did not fill the control's full height when a neighbouring label wrapped to two lines ("Dark on light"), leaving a white strip under "Off". Labels are now `display:flex` and the span `flex:1`. Regression assertion in the e2e panel-render check.

No other extension bugs were found: text size, contrast, dyslexia font (face loaded), reduce motion, reset, persistence, content-script apply at document_start, protected-page message, keyboard operation and axe (light and dark) all passed on the first run.

## Known limitations (deferred, not built)

- Per-site pause (turn AccessEase off for one site).
- Leaf `div`/`span` text is not scaled on px-sized sites (the floor covers paragraphs, list items, table cells, headings and form fields only). Scaling arbitrary leaves risks breaking fixed-height chrome.
- The range slider is not narrowed further at 260px panel width.
- The activeTab grant from a toolbar click cannot be verified in automation; the "click the AccessEase icon twice" advice in the first-run message relies on it.
- Text size on px-sized sites is approximate (floor-based); see Text scale above.
- Tabs styled by the all-sites "on" sweep have no content script until they are reloaded, so later setting changes reach them only when they are reloaded or become the active tab while the panel is open.
- Chrome hides tab URLs without host access, so protected pages are told apart from "not allowed yet" by the wording of Chrome's error message when the URL is unknown.
- Real Windows High Contrast themes were only emulated (`forcedColors: active`).
