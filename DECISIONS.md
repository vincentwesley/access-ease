# Decision log

1. **Bundled font: OpenDyslexic (Regular + Bold woff2).** Users search for and recognise it; SIL Open Font License 1.1 allows bundling and redistribution (Reserved Font Name "OpenDyslexic": ship unmodified, do not rename). Evidence that it improves reading is weak, so the UI says "dyslexia-friendly font" and makes no medical claim. Atkinson Hyperlegible Next (also OFL 1.1, single variable woff2) is the possible v1.1 alternative.
2. **Permissions: `storage`, `activeTab`, `scripting`, `sidePanel`; optional host permission `<all_urls>`.** Default install shows no "read all your data" warning. Persistence across sites and reloads is an explicit opt-in: `chrome.permissions.request` then `chrome.scripting.registerContentScripts`. Static `content_scripts` on `<all_urls>` rejected: it triggers the scary warning for every user. activeTab alone rejected as the only mode: access expires on navigation, so settings would not persist.
3. **Side panel, not popup.** A popup closes when focus leaves; the side panel persists across navigation and keeps the settings in view. Cost: Chrome 114+ only, acceptable.
5. **License: MIT** for our code; bundled fonts keep their own OFL 1.1 with OFL.txt shipped alongside. Not a fork of any project; all code is original.
6. **No bundler or build tool.** Plain ES modules, hand-written manifest, zero runtime dependencies. The extension is small; a build step adds supply-chain surface and contributor friction. Tests use Node's built-in runner on pure modules. Revisit only if TypeScript becomes necessary.
7. **No telemetry, no network calls, no remote code.** Explicit strict CSP for extension pages (decision 9); the only web-accessible resources are the two fonts and three lib modules (decision 8).
8. **`use_dynamic_url: true` on web_accessible_resources (fingerprinting).** Tried first, as asked. Real-Chromium e2e shows it works: the all-sites content script still dynamic-imports `lib/*.js`, the OpenDyslexic font loads on the all-sites path, and a page that fetches `chrome-extension://<fixed id>/fonts/...`, `lib/inject.js` or `manifest.json` is blocked. Kept. What this does NOT do: a page that is being styled can still see the per-session dynamic font URL and the `#accessease-style` element, so a site that looks can tell AccessEase is active; docs say so. Fallback if a future Chrome breaks it: make `content/apply.js` self-contained and drop `lib/*.js` from WAR (fonts stay). Not verified: Chrome versions other than the bundled Chromium (minimum stays 114).
9. **Manifest CSP** `default-src 'self'; script-src 'self'; object-src 'none'; connect-src 'none'; img-src 'self'; style-src 'self'; font-src 'self'; frame-src 'none'; base-uri 'none'; form-action 'none'`. Enforces the "no network" claim at browser level for our pages.
11. **Text size is an absolute root size computed in the page** (`round1(original root px * N/100)`), not a percentage, so `html{font-size:62.5%}` sites scale by exactly N%. The px-site floor is applied only when sampled text did not follow the root, and is based on the sampled paragraph size, so the hierarchy is not inverted on rem/em sites. Rounded to 0.1px rather than whole px to keep 110% at 110%. Rejected: per-element inline sizing (mutates the page, breaks with dynamic content) and `zoom`.
12. **Panel state honesty.** A status line shows whether AccessEase can act on the current page instead of showing live-looking controls; first-run copy is split into NO_ACCESS and PROTECTED; when Chrome hides the tab url, Chrome's executeScript error text is used as a hint for PROTECTED (heuristic, safe fallback).
13. **"Reset my settings"** (renamed from "Reset page settings") keeps the all-sites choice: it is not page appearance. It shows a self-clearing confirmation in `#notice` as well as the live-region announcement.
14. **Contrast options renamed** "Black on white" / "White on black" (internal values `light`/`dark` unchanged so stored settings keep working).
15. **Read aloud cut (user decision).** The whole feature was removed: Web Speech reader, chunking, page text extraction, the panel card, the `tts` setting and their tests. Reasons recorded: it was the largest source of review findings (announcement spam, pause/refresh bugs, cloud-voice privacy risk) and is not core to the reading-comfort value prop. Permissions are unchanged (`scripting` is still required for CSS injection). Old stored settings containing `tts` load fine; the key is dropped on the next save. It can return later as a separate, deliberately designed feature (the earlier design notes are in git history if the project is ever put under version control). This supersedes the earlier Web Speech / chunking / local-voice decisions, which were removed from this log (their numbers, 4 and 10, are intentionally skipped).
16. **All-sites logic moved to `lib/panel-logic.js`** (not web-accessible, unit-tested with a chrome stub). OFF clears every tab including the active one before `permissions.remove`, then re-checks; ON sweeps already-open tabs after registering. Rejected: injecting `content/apply.js` into open tabs (live updates) because it needs the saved `allSites` flag first and races with the save; the limitation is listed instead.
17. **Cross-window sync** through `chrome.storage.onChanged`, ignoring events while our own saves are in flight or when equal to the current state.
18. **Service worker reconciles on `permissions.onAdded/onRemoved`** so revoking access from chrome://extensions unregisters the content script.
19. **Text-size floor extended**: heading floors (1.6/1.35/1.2/1.05 x base) and `height:auto` on inputs, inside the strippable px-only block. Leaf div/span scaling deferred (risk to fixed-height chrome).
20. **Contrast**: background images removed from button-like/badge/chip/pill/tag elements; invalid fields get a dashed outline instead of the solid border. Dyslexia mode: no letter-spacing (only font, line-height, modest word-spacing).
21. **Forced colors**: system-colour block plus a check mark on the selected contrast segment (helps everyone who cannot rely on colour). Inactive dimming is 0.8 rather than the requested 0.6 because 0.6 fails axe contrast on hint text; the dimmed selected segment uses `--accent-dim`.
22. **Strict page CSP** (`default-src 'self'`): e2e shows the content script still applies styles and the dyslexia font loads (constructable stylesheet from the isolated world is not blocked by the page CSP), so no fallback was needed.
23. **Final-review polish.** Panel headings: "Contrast" is an h2 inside its legend; the font/motion and all-sites cards get visually hidden h2s ("Font and motion", "All sites") so there is a consistent h1 > h2 outline with no visual change. When all-sites is on but the tab was open before it, the status says to reload the page instead of pointing at the hidden button. After enabling all sites by keyboard, focus moves to the all-sites switch before the button hides. Screenshots wait for the 4s reset confirmation to clear before capture, use the UI labels "White on black"/"Black on white", and no longer claim photos/videos are untouched (the shots crop them out).
24. **All-sites enable ordering and rollback.** The grant fires `permissions.onAdded`, which wakes the service worker's reconcile; it must never read `allSites=false` and unregister the script the panel is registering. So the panel now saves `allSites:true` first, then registers, then calls `ensureConsistent(true)`; the worker also re-reads settings after reconciling and re-runs if they changed. If register fails after the grant, the setting is rolled back, the permission is removed, and the panel says so (or says Chrome still holds access if removal failed). Own storage echoes are remembered (`consumeEcho`, recorded by `writeMerged`, see 29) so a late echo of an older own save cannot revert a newer local value. If tabs.query fails or there is no tab id, the status shows "Not active on this page" instead of "Checking...". Not done: an e2e that drives the real optional-permission onAdded path (Playwright cannot answer the permission prompt); covered by unit tests with stubs.
25. **All-sites flow, second review.** `update()` now returns the save promise; the enable path awaits it, so a failed `storage.set` aborts and rolls back (setting off, permission removed, honest message) instead of reporting "on" and being unregistered by the reconcile. The re-read/re-check was made a shared `reconcileFresh(load)` in `lib/allsites.js`, used by both the service worker and panel init, so a second panel opening mid-enable cannot unregister the script from a stale snapshot. When the worker finds the setting on but access revoked (chrome://extensions), it writes `allSites:false` to storage; open panels follow via `storage.onChanged`, and the panel also refreshes its status on `permissions.onRemoved`.
26. **All-sites flow, third review.** Panel saves now re-read storage and write only the changed keys over it, so a background `allSites:false` (revocation) is never overwritten by a stale snapshot. `adoptExternalSettings` no longer treats every event during an in-flight save as an echo: an external `allSites` change is adopted (only that key) even then. On `permissions.onRemoved` the panel runs `reconcileFresh`, clears the setting if access is gone, and only then refreshes the UI. `registerApplyScript` is idempotent: a duplicate-id rejection from a racing context is success if the script is registered afterwards; a real failure still rejects.
27. **Revocation write-backs merge at write time.** A shared `setAllSitesOff()` in `lib/settings.js` does load -> merge `{allSites:false}` -> save, used by the service worker and by the panel (init and `permissions.onRemoved`), so a concurrent textScale/contrast edit is never reverted by a stale snapshot. The panel's `permissions.onRemoved` handler writes through `writeMerged` (see 29), which records the echo only if a write really happens; init runs before the storage listener exists, so it records nothing. Regression test: the background stub stores full settings and textScale survives.
28. **E2E flake root cause: a no-op save racing another context's write.** `chrome.storage` has no transactions, so the panel's merged save (read, merge, write) could overwrite an `allSites` written in between by another context; the test's `open()` clicks Reset (a no-op on defaults) and then the test wrote `allSites:true` from the worker, occasionally landing inside that window and being reverted. Product fix: the panel skips the write when the merged result equals what is stored. The remaining window only exists for real, changing edits made at the same instant in two contexts, which storage cannot prevent.
29. **Echoes come from what was written.** The panel's save is a merge over stored settings, so the local snapshot is not what lands in storage. `writeMerged` (`lib/panel-logic.js`) does load -> merge -> write and records the echo from the value actually written, only when a write happens (skip-if-equal leaves no phantom echo; a failed write removes its echo). It runs inside the panel's save chain (`update()` calls it from `saveChain.then`), and `permissions.onRemoved` now goes through `update({allSites:false})` too (see 33). `adoptMerged` rules are in 31/34. `setAllSitesOff` also skips the write when `allSites` is already false.
30. **All-sites enable rolls back on thrown errors.** `ensureConsistent(true)` returning false throws, and the tab sweep (including `getCss()`) runs inside the guarded region, so any thrown error after the grant rolls back (setting off, permission removed, honest message). Sweep failures do NOT throw: `sweepTabs` returns `{failed, unknown}` and the enable still succeeds, telling the user other tabs update on reload.
31. **All-sites OFF handles a failed save.** The panel awaits `update({allSites:false})`; on failure it shows the save notice and still drops the permission. Storage may keep a stale `allSites:true`. Originally `adoptMerged` adopted the merged value, so the next ordinary edit re-read that stale true and re-checked the box while the permission was gone; fixed by never adopting `allSites` in `adoptMerged` (34). The stale value is healed by the next reconcile (init or `permissions.onRemoved`).
32. **Registration never unregisters first.** `registerApplyScript` registers; on a duplicate-id error with the script present it calls `updateContentScripts`, so another context's registration is never destroyed in a gap. `reconcileFresh` re-checks `isRegistered` before returning ok. Not covered: real-Chrome concurrency (unit stubs only).
33. **`permissions.onRemoved` writes through the save chain.** The handler corrects the checkbox/settings and re-renders first, then calls `update({allSites:false})` (same `saveChain`, `writeMerged`, echo bookkeeping), so a revocation write can no longer lose an update against a concurrent save, and a write failure cannot skip the UI correction. Init's `setAllSitesOff` stays outside the chain on purpose: it runs before the controls and storage listener exist, so no `update()` can be in flight.
34. **`adoptMerged` is conservative.** It never adopts `allSites` (the live permission check owns it; external changes come via `adoptExternalSettings`), never a key the patch just wrote, nothing while a newer save is queued, and nothing while a save has failed (`saveFailed` in the panel, cleared once a successful write matches local state apart from allSites). Reason: after a failed save, local values are not in storage, and adopting the merge would silently revert what the user still sees. Trade-off: after a failure, another context's changes to untouched keys are not adopted until local and storage agree again.
35. **Echo list capped at 50** in `writeMerged` (`MAX_ECHOES`), so a run of saves that never echo back cannot grow it without bound. The unused `noteOwnSave` was removed. When the cap is hit the oldest echo is dropped; a very late echo of that save would then be treated as an external change (harmless in practice: it only matters after 50 saves with no echo).
36. **Registration helpers tolerate races.** `unregisterApplyScript` swallows an unregister error when the script is gone afterwards (another context removed it: "Nonexistent script ID"), so `disableAllSites` still removes the permission; a real failure with the script still registered rejects. In `registerApplyScript`, `updateContentScripts` failing is non-fatal: if the script is still registered it stays, if it vanished it is registered again.
37. **Failed saves are retried (dirty keys).** Before, a failed save left the panel silently diverged from storage: `writeMerged` writes only patch keys so the failed key was never retried, `saveFailed` blocked adoption forever, and the next successful save cleared the notice. Now the save bookkeeping lives in `createSaver` (`lib/panel-logic.js`, injected render/apply/setSticky/write so it is unit-tested). A failed write adds its keys to a dirty set; every later write merges the dirty keys (with their current local values) into its patch; the "could not save" notice stays up and adoption stays blocked while any key is dirty. A key leaves the set only when a write succeeded and storage holds the local value for it (the `savedMatchesLocal` rule applied to those keys, so an unrelated external change cannot pin the notice forever); once none are dirty the notice clears and `adoptMerged` resumes, adopting other contexts' changes. This supersedes the `saveFailed` flag in 34.
38. **`permissions.onRemoved` fallback.** If `reconcileFresh` throws, the handler asks `hasAllSitesPermission()`; if access is gone it treats the setting as revoked (checkbox off, `update({allSites:false})`) instead of leaving a stale checkbox.
39. **`registerApplyScript` re-register is guarded.** When `updateContentScripts` fails and the script vanished, the fallback `registerContentScripts` can itself hit a duplicate id (another context registered in the gap). It now re-checks `isRegistered()` and only rethrows if nothing is registered. Tested both ways.
